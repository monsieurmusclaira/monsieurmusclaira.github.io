## Follow-up verification

### 1. Crawl test timeout
Cause: `pages.spec.ts` "every route has one meaningful H1…" issued ~1,900 unique `HEAD` requests (387 links + 1,531 assets) one at a time after visiting 21 routes; profiling in WebKit showed route navigation at ~70 ms each but the `HEAD` loop at ~7.8 s alone, which stretched past the timeout under load. Fix: the checks now run in concurrent batches of 50 with every assertion kept (`test:` commit). The crawl test now takes ~14–22 s per project at 3 workers (was ~19–22 s unloaded and >60 s loaded).

### 2. Env test fragility
Not reproduced: a cold `node_modules/.astro` inside the full `npm test` flow (build 1 m 25 s, `test:verify` 210/210) and the env tests alone with a cold cache (first build 73 s, the next two 5 s and 4 s) both passed. The only cold-cache exposure was the default-case build, which doubled as the first full image build. Hardening: the default case now reads the `dist` that `npm test` just built with a default environment instead of running a third build; the two remaining builds run asynchronously (so Vitest's timeout can fire) with a 64 MB output buffer, and still surface stderr. The three behaviours remain covered (default → `true`, `PORTFOLIO_ANALYTICS_DISABLED=true` → `false`, malformed value → error naming the variable). Root cause of the one earlier failure is unproven.
